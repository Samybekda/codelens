À propos de CodeLens

Projet conçu dans le cadre de la Licence 3 MIAGE / MIASHS à l'Université Toulouse III – Paul Sabatier.

CodeLens est une application web conçue pour apporter une analyse rapide, claire, visuelle et 100% factuelle de n'importe quel dépôt GitHub public, sans artifice inutile ni complexité superflue.

🎯 Compétences mobilisées

🐍

Programmation Python & Flask

Découpage en couches modulaires (services, base de données, vues Jinja2), gestion d'exceptions et architecture MVC propre.

🌐

Consommation d'API REST

Requêtes HTTP sécurisées avec requests, pagination GitHub par en-têtes Link, gestion des quotas (Rate Limit) et format JSON.

🗄️

Persistance Relationnelle SQLite

Création d'un schéma SQL propre, requêtes paramétrées contre les injections SQL, sérialisation JSON des synthèses pour relecture hors-ligne.

📊

Visualisation & Frontend Vanilla

Interface responsive en CSS3 moderne (Flexbox & Grid), JavaScript pur sans framework lourd et graphiques interactifs avec Chart.js.

🧪

Tests & Qualité Logicielle

Suite de tests automatisés avec pytest couvrant la détection des extensions, les règles de complexité, le parsing et les routes HTTP.

🛡️

Sécurité & Bonnes Pratiques

Aucun token GitHub hardcodé, validation stricte des URLs, aucune exécution de code distant (analyse en lecture seule).

⚙️ Seuils de complexité configurables

Pour la détection des fichiers nécessitant une attention particulière, CodeLens utilise des règles déterministes et transparentes :

  • Longueur excessive : fichiers de plus de {{ thresholds.line }} lignes.
  • Concentration de fonctions : fichiers contenant plus de {{ thresholds.function }} définitions de fonctions.
  • Concentration de classes : fichiers contenant plus de {{ thresholds.class }} déclarations de classes.

Ces valeurs sont définies dans le module central config.py et peuvent être ajustées via variables d'environnement.

💡 Argumentaire pour la soutenance L3

Questions fréquentes du jury & réponses clés :

Pourquoi ne pas attribuer une note globale (ex: 15/20) au dépôt ?

Une note unique sur du code est arbitraire et trompeuse. CodeLens privilégie un rapport 100% factuel et mesurable (nombre de fichiers, part des langages, présence de tests et de documentation), conformément à la rigueur scientifique attendue en MIASHS / MIAGE.

Comment l'arborescence est-elle récupérée sans faire des centaines d'appels API ?

Grâce à l'endpoint Git Trees de l'API GitHub (/git/trees/{branch}?recursive=1), l'intégralité des fichiers et dossiers est rapatriée en une unique requête HTTP, préservant ainsi les quotas d'API.

Pourquoi du JavaScript Vanilla plutôt que React ?

Pour un projet de L3, le JavaScript natif évite la surcharge d'un bundler (Webpack/Vite), reste 100% compréhensible ligne par ligne lors d'une soutenance, et s'intègre parfaitement avec le moteur de template natif de Flask (Jinja2).
